# 跨设备会话同步

在运行 SSH 和 tmux 的主机上启动服务。每台主机使用独立数据库和令牌；同一主机的各设备填写同一个同步地址和令牌。服务只保存会话 ID、目录和命令名称，不保存 SSH 密码或密钥。

```bash
export RDT_SYNC_TOKEN='替换为随机长令牌'
python3 backend/server.py --host 127.0.0.1 --port 8765
```

默认数据库位于 `~/.local/share/remote-dev-terminal/sessions.db`，可用 `--database` 修改。请通过环境变量或权限受限的服务配置提供令牌，不要提交到代码仓库。

例如在该主机的 frpc 配置中增加以下 TCP 代理，公网 8080 转发到本机 8765（需已有 frps 并允许该端口）：

```toml
[[proxies]]
name = "remote-terminal-sync"
type = "tcp"
localIP = "127.0.0.1"
localPort = 8765
remotePort = 8080
```

服务本身使用 HTTP；直接经公网访问会暴露令牌和会话元数据。公网使用时应在入口配置 HTTPS，或使用可信的加密隧道，再填写相应的 `https://地址:端口`。请按实际 frp 和反向代理环境配置，此仓库不会自动修改远程服务器或 frp。

在 Android 主机编辑界面填写「同步服务地址」和「同步服务令牌」；桌面端在主机编辑中填写相同字段。SSH 地址、端口、用户名和凭据仍需在各设备单独配置，且应连接到同一台主机的同一用户。每次启动时客户端会读取所有已配置主机的共享会话，显示在 Android 首页或桌面侧栏；点击会话才会接入远端终端。启动新任务时会登记会话；点击「共享会话」可以再次读取当前列表。关闭标签会从共享列表移除记录，但不会杀死远端 tmux。

恢复依赖主机已安装 tmux，且对应会话仍存在。服务只负责记录会话信息，不转发终端数据；终端继续通过 SSH 连接。连接同步服务失败时客户端会提示，当前版本不会自动重试失败的写入，因此应恢复连接后重新创建需要共享的任务。服务不追踪 tmux 是否被外部终止；失效记录可从客户端接入后关闭移除。切换设备接入会使原设备的 tmux 客户端脱离。

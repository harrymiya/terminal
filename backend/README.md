# 跨设备同步服务

同步服务为每个账号独立保存主机资料、Agent 预设、工作区和会话记录。服务不保存 SSH 密码、私钥或终端输出；终端连接仍直接通过 SSH 建立。

## 启动

在可被各设备访问的主机运行：

```bash
python3 backend/server.py --host 0.0.0.0 --port 8765
```

默认数据库位于 `~/.local/share/remote-dev-terminal/sessions.db`，可用 `--database` 修改。首次启动且数据库中没有账号时，会创建管理员账号 `lirui`，初始密码为 `123123`。可通过 `RDT_SYNC_BOOTSTRAP_USERNAME` 和 `RDT_SYNC_BOOTSTRAP_PASSWORD` 在首次启动前指定初始账号。已有账号的数据库不会重建初始账号。

## 客户端登录和同步

在 Android 的登录页或 PC 系统设置中填写同步服务地址，然后使用账号和密码登录。首次创建的管理员可以在系统设置的「用户维护」中增删、编辑账号并重置密码；普通账号看不到用户维护入口。每个账号只能访问自己的同步数据。

## 主机与会话的权威来源

服务端的账号会话记录是跨设备会话列表的权威来源，记录按「账号 + 主机档案 ID + SSH 用户名 + 会话 ID」隔离。各设备只负责本机 SSH/tmux 连接和显示；一次同步请求失败不会被当成空列表，也不会据此关闭本机会话。

主机身份使用服务端主机档案 ID。首次同步时，服务端会用唯一匹配的 SSH 用户名和连接端点/旧别名把新档案归并到现有 ID；客户端收到后保存该规范 ID。内网地址和外网地址只是连接路由，实际选择哪条路由不改变主机身份。旧指纹、手动同步 ID 和地址别名只用于迁移匹配；存在歧义时不会任意挑一个档案。SSH 用户名是会话隔离的一部分，因此同一 SSH 主机使用不同用户名会显示为不同的会话集合。每条已填写的 SSH 地址都必须同时填写端口；客户端不会为缺失端口补默认值。

主机档案的显式编辑会上传服务端；自动拉取和会话目录同步由每台设备自己的「跨设备自动同步」开关控制，默认关闭。打开后可在系统设置里指定 5–300 秒的轮询周期。此开关和周期保存在本机，不会被账号同步覆盖。

工作区和 Agent 列表支持并发合并。客户端会在本机记住账号对应的同步版本，离线更改会在连接恢复后合并推送。删除用户时，该账号的会话、主机资料、工作区和版本历史也会删除。

## 网络安全

服务使用 HTTP。仅在可信局域网中直接使用；跨公网访问时应在入口配置 HTTPS，或通过可信加密隧道访问。不要把服务直接暴露到不可信网络。服务不会自动修改远程服务器、防火墙、frp 或反向代理配置。

例如在已有 frps 的情况下，可将公网 8080 转发到服务所在主机的 8765：

```toml
[[proxies]]
name = "remote-terminal-sync"
type = "tcp"
localIP = "127.0.0.1"
localPort = 8765
remotePort = 8080
```

远端仍需要安装 tmux 才能在 SSH 断开后恢复终端会话。服务只保存会话元数据，不追踪 tmux 会话是否被其他程序终止；切换设备接入同一个 tmux 会话会使原设备的终端客户端脱离。
